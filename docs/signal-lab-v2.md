# Signal Lab V2 — обучающая модель паттернов

## Цель

Signal Lab V2 превращает визуальные сетапы команды в проверяемые рыночные эпизоды. Он не добавляет торговых команд и не считает Telegram-скриншот доказательством преимущества.

Основной маршрут:

`источник гипотез → кандидат → ручная разметка → контрпримеры → версия формулы → наблюдаемый результат → BETA-проверка → отдельное решение о выводе в радар`.

## Обязательные продуктовые контракты

1. Паттерн состоит из контекста, структуры, действия, подтверждения, отмены и результата.
2. Кандидат не называется подтверждённым сигналом.
3. Один рыночный эпизод не создаёт серию дублей.
4. На графике должны быть видны выбранные экстремумы, уровень, подтверждение, цена отсчёта, отмена и фактическое продолжение.
5. Секундный, минутный и пятиминутный контекст являются реальными отдельными агрегациями.
6. Неизвестные или недоступные данные отмечаются явно.
7. Нельзя утверждать наличие крупного игрока, спуфинга, выноса конкретной группы участников или набора позиции без подтверждающих данных.
8. Старые события сохраняют исходную версию формулы и не пересчитываются задним числом.

## Первая библиотека гипотез

- пробой каскада;
- пробой уровня после нескольких тестов;
- ложный пробой с возвратом;
- нож с быстрым выкупом;
- зеркальная заточка с быстрым сливом;
- выход из сжатия;
- удержание наблюдаемой ликвидности;
- переставление наблюдаемой ликвидности;
- каскад ликвидаций.

Термины «участник», «заточка», «алгос», «пробой со снятия» и «пробой со сквизом» не получают выдуманной production-формулы. Они хранятся как гипотезы и раскладываются на структуру, действие и подтверждение.

## Ручная разметка

Вердикты:

- `valid` — паттерн собран правильно;
- `weak` — конструкция допустима, но слабая;
- `false_positive` — детектор увидел паттерн там, где его нет;
- `missed_pattern` — реальный паттерн не был найден;
- `duplicate_episode` — повторное событие того же движения;
- `wrong_pattern` — событие есть, но тип определён неверно;
- `insufficient_data` — данных недостаточно.

Разметка хранит значимые экстремумы, уровень подтверждения, цену отсчёта, уровень отмены, состояние паттерна, episode ID, причины и комментарий.

## Эпизоды и дубли

События объединяются только когда совпадают монета, канонический паттерн и направление, находятся в допустимом временном окне и рядом с одной ценовой структурой. Завершённый или отменённый эпизод не может «воскреснуть» от следующего сигнала.

## Готовность формулы

Статус готовности является процессным фильтром, а не доказательством доходности:

- `hypothesis`;
- `labeling`;
- `exploratory`;
- `beta_eligible`;
- затем отдельный ручной `radar_review_required`.

Для BETA нужны не только правильные примеры, но и контрпримеры, достаточная доля LIVE-данных и единая версия формулы.

## Параллельная интеграция

Ветка создаётся изолированно. После слияния двух параллельных работ она переносится на актуальный `main`, затем выполняются:

1. сравнение конфликтующих файлов;
2. подключение UI и IndexedDB-миграции;
3. syntax checks;
4. полный `npm test`;
5. проверка loading / empty / error / stale;
6. проверка старых записей Signal Lab;
7. живая проверка реальных событий;
8. только после этого — готовность PR к слиянию.
