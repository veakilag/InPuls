# Fast market cold start v1

## Проблема

После исправления Service Worker обычный F5 стал стабильным, но первый экран рынка заполнялся постепенно. Binance `!miniTicker@arr` на старте мог прислать только изменившиеся инструменты, а полный REST-снимок в приложении запускался с задержкой и отменялся первым WebSocket-пакетом. NATR и корреляция дополнительно прогревались партиями по шесть монет раз в пять секунд.

## Решение

- сразу параллельно запросить полный `/fapi/v1/ticker/24hr` через публичные Futures REST-хосты;
- после открытия только core `!miniTicker@arr` WebSocket добавить одним пакетом отсутствующие в live-потоке инструменты;
- не перезаписывать монеты, уже увиденные в более свежем WebSocket-пакете;
- ускорить только два известных таймера `warmupRadarHistory`: первый запуск с 1500 до 250 мс и период с 5000 до 1000 мс;
- после назначения этих таймеров восстановить стандартные браузерные `setTimeout` и `setInterval`;
- при ошибке REST оставить существующий WebSocket и штатный fallback без изменений.

## Не затрагивается

- формулы сигналов, рейтинг и Market Memory;
- стакан, Worker, Tape и Footprint;
- настройки, workspace, IndexedDB и история Signal Lab;
- reconnect и маршрутизация остальных Binance-каналов.

## Проверка

- список рынка появляется полным снимком, а не накапливается десятками секунд;
- live WebSocket продолжает обновлять снимок;
- NATR и корреляция прогреваются заметно быстрее;
- F5 остаётся рабочим;
- полный `npm test` и Chromium runtime smoke проходят.
